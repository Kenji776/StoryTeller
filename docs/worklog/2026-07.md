# Worklog — 2026-07

## 2026-07-27 — Phase 1: foundation for player-supplied AI credentials

**Goal:** Replace the single server-side API key with per-player provider choice
and credentials, supporting OpenAI, Anthropic, Google, Ollama, and arbitrary
OpenAI-compatible endpoints. This entry covers Phase 1 of 6 — the
provider-agnostic foundation only, not yet wired to anything.

**Changed:**
- `CLAUDE.md` — filled in the Project Overrides table (test/coverage commands,
  `LOG_DIR`, `MODULE_ROOT`); recorded that no typecheck or lint command exists.
- `package.json` — added `test`, `test:integration`, `coverage` scripts using
  Node's built-in runner. No new dependencies.
- `server/services/llm/config.js` + test — boundary validation and redaction for
  untrusted AI configurations.
- `server/services/llm/errors.js` + test — `LLMRequestError`, status→kind
  classification, retryability, player-facing messages.
- `server/services/llm/http.js` + test — the single request/failure-mapping path
  all adapters will share; `fetch` injected.
- `docs/` — bootstrapped (none existed): README, architecture, testing, module
  doc, ADRs 0001 and 0002.

**Decisions:** Host's credential powers the lobby, held in memory only and never
in `LobbyStore` (whose `persist()` writes the whole object to disk) — ADR 0001.
Adapters call HTTP directly rather than through vendor SDKs, so per-request keys
are natural and one code path covers all five providers — ADR 0002. Operator
chose all four recommended options when asked (host key, five providers,
separate optional image key, `node:test`).

**Verification:**

- RED observed before each implementation per `TDD-2`: config 29/33 failing with
  assertion failures (`Missing expected exception`, property reads on the stub's
  `null`), errors 32/33 (`null !== 'auth'`), http 16/16. No `ModuleNotFound` or
  syntax failures among them.
- `npx fallow dead-code` and `npx fallow dupes` → zero findings against
  `server/services/llm`. `fallow audit` could not run (needs a git worktree,
  which fails on this network share).
- No typecheck or lint gate exists in this project; both reported as unset.

- `docker-compose.yml` holds live OpenAI, Anthropic, and ElevenLabs keys in

- ~~Decision still needed before Phase 5: whether a player's AI configuration is

## 2026-07-27 — Phase 2: OpenAI and Anthropic adapters, provider registry

**Goal:** Parity with the current two providers behind the new adapter
interface, plus the live model listing that replaces the hardcoded model arrays.

**Changed:**
- `server/services/llm/providers/openai.js` + test — chat completions and model
  listing; non-chat models (embeddings, audio, image) filtered out of the picker.
- `server/services/llm/providers/anthropic.js` + test — Messages API, system
  lifting, turn merging, multi-block reply concatenation, model listing.
- `server/services/llm/registry.js` + test — the only list of which providers
  exist; `listProviders()` returns serialisable metadata for the browser.
- `docs/modules/llm.md` — adapter contract and the per-provider quirks absorbed.

**Decisions:** `listModels` lives on the adapter rather than in a shared switch,
so a new provider is one file plus a registry line. Anthropic turn-merging and
the inserted `(begin)` turn are new behaviour, not parity — StoryTeller cannot
guarantee alternating roles and the previous code would have 400'd mid-game.
`sanitizeForLLMName` was simplified to a single pass; verified behaviourally
identical to the original across 17 inputs including hyphens, control
characters, and non-Latin scripts.

**Verification:**
- `npm test` → 163 pass, 0 fail (117 → 145 → 163 across the three units).
- RED observed before each: OpenAI 31/31, Anthropic 28/28, registry 18/18.
- `npx fallow dead-code`/`dupes` → one finding in scope: 13 duplicated lines
  between `providers/openai.js` and the legacy `llmService.js`. Declined —
  that is the sanitiser, duplicated only until Phase 4 deletes `llmService.js`.

**Open:**
- Caught and fixed during this phase: writing `\uXXXX` escapes through the file
  tooling injected raw control bytes into `openai.js`, and an attempted repair
  put a literal `s` into a character class, which mangled any name containing
  "s" ("Sisyphus" → "Si_yphu_"). Both fixed, both now pinned by regression
  tests. All files verified plain-ASCII. Avoid `\uXXXX` in written source;
  build such characters with `String.fromCharCode` instead.
